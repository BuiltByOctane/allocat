# What's New Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin-managed "What's new" changelog surfaced in Profile, a dashboard card, the local notification inbox and a push.

**Architecture:** Global `whats_new_entries` table (authenticated read, service-role write) + public `whats-new` storage bucket. App reads via a server action through React Query, cached in localStorage for offline; "seen" state is per device. Admin uses RSC + server actions behind `requireAdmin()`, notify reuses `broadcast()` from `lib/server/push-broadcast.ts`.

**Tech Stack:** Next.js 16 App Router, React 19, Supabase, TanStack Query 5, Dexie (inbox only), Tailwind v4, `react-markdown` (already installed), vitest.

**Spec:** `docs/superpowers/specs/2026-10-31-whats-new-design.md`

## Global Constraints

- Tags allowed: exactly `new`, `improved`, `fixed`.
- Click URL for every surface: `/whats-new` (push uses `/whats-new?e=<entryId>`).
- localStorage keys: `allocat-whats-new-seen` (ISO timestamp), `allocat-whats-new-cache` (JSON entries). Every access in try/catch.
- Inbox row id: `whats-new:<entryId>`, kind `"whats-new"`.
- Inbox seeding: only entries with `notified_at` within the last 14 days.
- Markdown rendered with `react-markdown`, no `rehype-raw` (no raw HTML).
- Admin: `requireAdmin()` at top of every page and server action. No React Query / Dexie in `/admin`.
- Not in the sync engine; no `TABLE_SPECS` / `dispatch` entries.
- Imports use `@/` alias. Commit subjects short, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Empty table (no entries yet): card hidden, Profile dot hidden, page shows an empty state — no crash on `entries[0]`.
- Offline / server action throws: page renders cached entries; card/dot computed from cache.
- Admin edits an existing entry (no new `published_at`): must not re-trigger "unseen" for users who already saw it.
- Same entry notified twice, or reconciler runs on every mount: inbox must hold one row per entry (dedup by id before `recordNotification`).
- localStorage unavailable (private mode): seen = "never seen" is wrong for the card spam case — treat unavailable storage as "seen" for the dashboard card (don't nag), but still render the list.
